# Remove the wasted requests on dashboard mount

You are implementing a performance change in the Leaflet repo (Next.js 16.3 App Router, React 19, Replicache, SWR). Read `CLAUDE.md` first. This is Tier 2 of the PWA load audit (`plans/pwa/README.md`), covering the "kill wasted mount requests" and "limit eager prefetch" items.

## Context

On every mount of `/home` (and `/reader`, which shares the `(home-pages)` layout) a logged-in client fires these requests in addition to the document, the JS, and the Replicache pull:

| Request                                | Where it comes from                                                                                                                                                                                                                                                                                             | Why it is waste                                                                                                                                                                                                                                                                       |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/rpc/get_leaflet_data`       | `components/ThemeManager/ThemeProvider.tsx:58` calls `useLeafletPublicationData()` → `useLeafletData` in `components/PageSWRDataProvider.tsx:54-63`, which fetches unless a `StaticLeafletDataContext` is above it. The `(home-pages)` layout mounts `ThemeProvider` for the home leaflet with no such context. | The home leaflet is never in a publication. `get_leaflet_data` is a heavy nested select. `ThemeBackgroundProvider` (`ThemeProvider.tsx:483`) shares the SWR key, so it is one request, but still pure waste.                                                                          |
| `POST /api/rpc/get_profiles`           | `components/ActionBar/ProfileButton/ProfileButton.tsx:36` → `useRecordFromDid(identity.atp_did)`                                                                                                                                                                                                                | The viewer's own profile is already in `identity.bsky_profiles` from the identity payload.                                                                                                                                                                                            |
| server action `trackPageView`          | `components/TrackPageView.tsx:12` → `actions/trackPageView.ts:9` runs its own `resolveAuthToken` query on every route change                                                                                                                                                                                    | Needed for analytics, but the extra auth query per page view is avoidable.                                                                                                                                                                                                            |
| server action `getCurrentSessionToken` | `components/IdentityProvider.tsx:146`, every load with an identity                                                                                                                                                                                                                                              | Saved-accounts bookkeeping. The comment explains why it always refetches; a daily cadence achieves the same.                                                                                                                                                                          |
| `GET /home/icon`                       | `app/(app)/(identity)/(home-pages)/(writer)/home/icon.tsx` is `revalidate = 0`, `force-dynamic`, `fetchCache = "force-no-store"`, reads `cookies()`, and returns `Cache-Control: no-cache`                                                                                                                      | A second serverless invocation rendering a 32×32 PNG through satori per load. It reads a legacy `identity` cookie that current code never sets (the only readers are `icon.tsx:30` and `actions/login.ts:58`), so the DB branch never runs and the output is always the default icon. |
| N eager RSC prefetches                 | `SpeedyLink eager` on the home and reader nav buttons (`components/ActionBar/NavigationButtons.tsx:27,41`, `DesktopNavigation.tsx:92,232`) and the first six publications (`components/ActionBar/Publications.tsx:62,83,106`)                                                                                   | Each is a full dynamic render of a sibling route, all firing during hydration and competing with the current page's own requests on mobile. After plan 02 the server cost is small, but the client bandwidth cost at launch is not.                                                   |

Also found during the audit, a latent bug in the same area: `usePollData` (`components/PageSWRDataProvider.tsx:44`) uses the global SWR key `"poll_data"` while its fetcher closes over the nearest provider's `permission_token`, so a poll block inside any home card preview fetches with an arbitrary card's entity sets.

## Goal

After this change, a `/home` mount for a logged-in user makes exactly: the document, static assets, the Replicache pull, `getFactsForRoots` for the visible cards, the realtime channels, and `trackPageView`. Eager prefetches happen after the page is idle, not during hydration.

## Steps

1. **`get_leaflet_data` on the home leaflet.** In `app/(app)/(identity)/(home-pages)/layout.tsx`, wrap the `ThemeProvider`/`ThemeBackgroundProvider` subtree in `StaticLeafletDataContext` with a value built from `home_leaflet` (read the context type at `PageSWRDataProvider.tsx:19` and the cast pattern in `home/HomeLayout.tsx` around lines 43 and 200-236; the home leaflet has no `leaflets_in_publications` or `leaflets_to_documents`, so pass empty arrays). If the context shape makes that awkward, add an explicit prop to `ThemeProvider` (for example `standalone`) that skips `useLeafletPublicationData`. Prefer the context: it reuses the existing static path. Confirm with the Network panel that the request is gone on both `/home` and `/reader`.
2. **Own profile.** In `ProfileButton.tsx`, read avatar, handle, and display name from `identity.bsky_profiles` (check the shape in `src/identityPayload.ts` `bskyProfileFromCache`) and drop `useRecordFromDid` there. Keep `useRecordFromDid` for its other callers. If plan 02 made `bsky_profiles` nullable on a cache-only miss, fall back to `useRecordFromDid` only when it is null.
3. **`trackPageView`.** If plan 02 has landed, replace `resolveAuthToken(getValidAuthToken())` with the cached identity read and pass the fields `trackUserEvent` needs. If plan 02 has not landed, leave it and say so.
4. **`getCurrentSessionToken`.** In the effect at `IdentityProvider.tsx:138-165`, read the saved-accounts entry first (`readSavedAccountEntries` in `src/hooks/useSavedAccounts.ts`); skip the server call when an entry for `identity.id` exists and was written less than 24 hours ago (add an `updatedAt` to the entry if it lacks one). Keep the existing comment's concern intact: a re-login mints a new token, and a daily refresh still catches that.
5. **`/home/icon`.** Confirm nothing sets an `identity` cookie (grep `"identity"` across `app/`, `actions/`, `src/`, `middleware.ts`). If confirmed, delete `home/icon.tsx` and let the app-level `app/icon.svg` / `app/icon.png` apply, or replace it with a static PNG in the segment if the dashboard should keep a distinct icon. Do not keep a dynamic route for a static image.
6. **Eager prefetch timing.** In `components/SpeedyLink.tsx`, make `eager` mean "prefetch once the page is idle" rather than "on mount": gate it behind a small shared hook that flips true in `requestIdleCallback` (fallback `setTimeout` 1500 ms) after mount, so prefetches never overlap hydration and the critical requests. Keep the current eager set (home, reader, tabs, first six publications). Verify in the Network panel that the RSC prefetches now start after the pull and `getFactsForRoots` complete.
7. **`usePollData` key.** Change the key to include `permission_token.id` so each provider fetches its own polls, and check its consumers still resolve the right data.
8. **Tidy.** `NavStateTracker` is mounted twice in `(home-pages)/layout.tsx` (lines 34 and 56, both branches). It is harmless because of the module-scope guard; hoist it above the branch so it appears once.
